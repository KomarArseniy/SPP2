# Лабораторная работа №4 — TypeRush (гонка по тексту в реальном времени)

Многопользовательская веб-игра: несколько игроков получают **один и тот же текст** и печатают его наперегонки.
Машинки всех игроков двигаются по трассе **у всех одновременно** (WebSocket), побеждает тот, кто первым допечатал текст.

Только JavaScript, **без фреймворков** и без сборки: на клиенте обычный JS, на сервере Node.js + единственная библиотека `ws` (реализация протокола WebSocket).

## Запуск

Нужен Node.js 18+ (проверено на 22).

```bash
cd lab4
npm install
npm start
```

Откройте http://localhost:3000 в **двух окнах/вкладках** (лучше в разных браузерах или одно окно инкогнито), введите разные имена, нажмите «Готов».
Порт можно сменить: `PORT=4000 npm start` (PowerShell: `$env:PORT=4000; npm start`).

Тесты: `npm test` (9 автотестов на сервер).

## Соответствие требованиям

| Требование | Как выполнено |
|---|---|
| 1. Мгновенная синхронизация через WebSockets | Клиент шлёт `progress` при каждом нажатии клавиши; сервер раз в 100 мс рассылает всем `state` (позиции, скорость, фаза гонки). Обычных HTTP-запросов во время игры нет. |
| 2. Только JavaScript, без фреймворков | `server.js` (Node + `ws`), `public/app.js` — чистый JS и DOM API. Ни React, ни Express, ни сборщиков. |
| 3. Сохранение данных между запусками | Статистика игроков (гонки, победы, лучший/средний WPM) и история гонок пишутся в `data/data.json` (атомарно: запись во временный файл → `rename`). После перезапуска таблица лидеров на месте. |

Расширенные пункты (разрешение конфликтов, восстановление состояния, хостинг) не входят в базовую версию.
Небольшой бонус: клиент автоматически переподключается, а если игрок вернулся с тем же именем в ходе гонки, сервер возвращает его на место.

## Правила игры

Режим «слепая печать»: в каждой гонке игроки получают одни и те же **35 случайных, не связанных между собой слов** (строчные русские буквы, без знаков препинания, «ё» и латиницы). Видишь слово — печатаешь, не читая смысл.

1. Введите имя и нажмите «Играть». Нажмите «Готов».
2. Гонка стартует, когда готовы **все** игроки, либо через 20 с после первого «Готов».
3. Обратный отсчёт 5 с → гонка **без ограничения по времени**. Ввод пословный: **пробел — переход к следующему слову**, **Backspace стирает символы, в том числе в уже завершённом слове** (при пустом поле возвращает к предыдущему слову). Ошибки подсвечиваются красным, но машинка едет в любом случае — ошибки лишь снижают точность и «чистый» WPM. Ошибка портит только своё слово. Вставка из буфера запрещена.
4. Как только кто-то финишировал, у остальных запускается таймер **25 секунд**, чтобы успеть закончить. Когда все финишировали (или время на добивание вышло) — таблица итогов, через 12 с — новый раунд. Не успевшие показываются с процентом пройденного пути.

WPM = (верно набранные символы / 5) / минуты. Точность = доля нажатий без ошибок (недописанные символы слова тоже считаются ошибками).

## Архитектура

```
Браузер A ──┐                       ┌── data/data.json (статистика)
Браузер B ──┼── WebSocket /ws ──► server.js (единый источник правды)
Браузер C ──┘                       └── texts.js (тексты гонок)
```

Сервер — **единственный источник правды**: клиент сообщает только «сколько символов правильно набрано», а скорость, места и итоги считает сервер.
Так никто не может объявить себя победителем: сервер ограничивает скорость (≈300 WPM) и игнорирует невозможный прогресс.

Фазы игры (конечный автомат на сервере): `waiting → countdown → racing → results → waiting`.

### Протокол сообщений (JSON)

| Направление | Сообщение | Назначение |
|---|---|---|
| клиент → сервер | `{type:"join", name}` | войти в игру |
| клиент → сервер | `{type:"ready", value}` | отметка «Готов» |
| клиент → сервер | `{type:"progress", pos, correct, typed, errors}` | прогресс (pos — пройдено символов, correct — из них верно) |
| сервер → клиент | `{type:"joined", id, name}` | подтверждение входа |
| сервер → клиент | `{type:"error", code, message}` | ошибка (имя занято и т. п.) |
| сервер → клиент | `{type:"state", phase, text, players[], results[], …}` | снимок игры (≈10 раз/с во время гонки) |
| сервер → клиент | `{type:"leaderboard", rows[]}` | таблица лидеров |

## Как это защищать (коротко)

- **Почему WebSocket, а не HTTP:** постоянное двустороннее соединение — сервер сам присылает обновления, без опроса. Задержка — единицы миллисекунд.
- **Как работает синхронизация:** клиент → `progress`; сервер проверяет и обновляет состояние; раз в 100 мс `state` уходит всем подключённым.
- **Почему считает сервер:** клиенту нельзя доверять (его можно подделать). Сервер хранит время старта и считает WPM сам.
- **Где данные:** `data/data.json`, запись атомарная (tmp-файл + rename), с небольшой задержкой, чтобы не писать на диск на каждое событие. Также сохраняются при остановке сервера (SIGINT/SIGTERM).
- **Что можно улучшить (расширенные пункты):** комнаты, разрешение конфликтов при одновременных правках, восстановление состояния после обрыва, деплой на хостинг.
